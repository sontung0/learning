Inter-Application Communication

Wire individual Spring Boot apps into a streaming pipeline by aligning destinations — and tell each instance where it sits in the fleet.

1. Pipelines Are Built From Adjacent Destinations

The typical Spring Cloud Stream deployment is not a single app — it is a multi-application pipeline where one microservice hands data to the next. You build this not with code, but by correlating the input and output destinations of adjacent applications.

Suppose a Time Source sends to a Log Sink. Both point at a shared destination named ticktock:

# Time Source (producer)
spring.cloud.stream.bindings.output.destination=ticktock

# Log Sink (consumer)
spring.cloud.stream.bindings.input.destination=ticktock
Key idea: the two applications never reference each other directly. They agree only on a destination name. The broker is the meeting point; the destination is the contract.

2. Consumer Groups Make the Pipeline Scale

When multiple instances of the same sink application share a destination, they form a consumer group (Lesson 0003). Each message is delivered to exactly one instance in the group, giving you load-balanced consumption. Set the group on the consumer side:

# Log Sink — instance A, B, C all share this group
spring.cloud.stream.bindings.input.group=log-sink-group

Without a group, each instance receives its own copy of every message (broadcast / pub-sub). With a group, the fleet shares the load.

3. Instance Index & Instance Count

When you scale an application to N instances, each instance can be told how many siblings exist and which one it is:

PropertyMeaningDefault
spring.cloud.stream.instanceCountTotal number of instances of this application1
spring.cloud.stream.instanceIndexThis instance's position (0-based)0

For three HDFS sink instances, all set instanceCount=3; the individual apps set instanceIndex to 0, 1, and 2 respectively.

Why it matters: these two properties are critical for partitioning behavior — certain binders (notably Kafka) require them to split data correctly across consumer instances. Misconfigure them and partitions will be assigned incorrectly or data will be skipped.

4. Who Sets These Properties?

DeploymentWho sets instanceCount / instanceIndex
Spring Cloud Data FlowConfigured automatically by the deployer
Independent launch (manual, K8s, etc.)You must set them correctly per instance

If you deploy outside Data Flow — for example, as separate Kubernetes pods or plain JVM processes — you are responsible for giving each instance its unique index and the correct total count.

5. Putting It Together: A Three-Stage Pipeline

# Stage 1 — Time Source (HTTP → messages)
spring.cloud.stream.bindings.output.destination=ticktock

# Stage 2 — Log Sink (consumer group, 3 instances)
spring.cloud.stream.bindings.input.destination=ticktock
spring.cloud.stream.bindings.input.group=log-sink-group
spring.cloud.stream.instanceCount=3
spring.cloud.stream.instanceIndex=0   # 1, 2 on the other instances

# Stage 3 — HDFS Sink (downstream of log-sink via another destination)
spring.cloud.stream.bindings.input.destination=processed-logs
spring.cloud.stream.bindings.input.group=hdfs-sink-group

Each stage knows only its destinations and its place in the fleet. The broker stitches the pipeline together.

Assessment

Retrieval Practice:

1. Two Spring Cloud Stream apps need to form a pipeline. What single piece of configuration makes the producer's output reach the consumer, and do the apps ever reference each other directly?

2. You launch three instances of a sink application against the same destination. What property turns them into a load-balanced consumer group instead of three independent broadcast receivers?

3. Name the two properties that tell an instance about the size of its fleet and its own position. What are their default values?

4. Which deployment platform sets those two properties automatically, and what must you do when launching instances independently?

5. Why are instance count and instance index especially important for the Kafka binder — what breaks if they are wrong?
