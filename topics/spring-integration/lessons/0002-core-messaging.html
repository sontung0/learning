Core Messaging: Chapter Roadmap

A short orientation before we go deep on channels — what this chapter covers, and what's deliberately deferred.

Why this lesson is short

The Core Messaging reference page introduces no new API of its own — it is a one-paragraph map of the chapter you're about to work through. Per our strict reference-order rule (one page = one lesson), it still earns its own lesson, but the job here is orientation, not new mechanics. Lesson 0003 picks the real code back up with Message Channels.

Mission tie-in: Knowing the shape of a reference chapter before diving in is itself a skill for independent mastery — it lets you predict what's coming and slot new facts into a mental model instead of learning them as a disconnected pile.

What "core messaging" bundles together

Per the reference: [ref]

This section covers all aspects of the core messaging API in Spring Integration. It covers messages, message channels, and message endpoints. It also covers many of the enterprise integration patterns, such as filter, router, transformer, service activator, splitter, and aggregator. This section also contains material about system management, including the control bus and message history support.

That's a wide net. Our `RESOURCES.md` splits it into the sequence below, in strict order, so we cover it as separate, digestible lessons rather than one sprawling page.

Deliberately deferred, not skipped

Two things the summary mentions are not in this chapter's lessons — they live later in `RESOURCES.md`, in their proper strict-order slot:

  • The individual EIP endpoints — filter, router, transformer, service activator, splitter, aggregator — get their own dedicated phases (Phase 4 Message Routing onward). Core Messaging only name-drops them; we'll build each one for real when its turn comes.
  • System management — control bus, message history, metrics — is Phase 8, after the messaging fundamentals and DSL are solid. Operating a flow well requires first knowing what's flowing.
Why this matters for retention: resist the urge to peek ahead and learn these out of order. Each concept is introduced once its prerequisites are in place — jumping ahead trades storage strength for a shallow, disconnected first impression.
