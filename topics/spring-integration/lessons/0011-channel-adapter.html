Channel Adapter

The message endpoint that connects a single producer or consumer to a channel — the simplest way to bridge your application code with the messaging system.

Why this lesson exists

A channel adapter is a message endpoint that connects a single sender or receiver to a MessageChannel. It's the simplest endpoint type: there's no routing, splitting, or aggregation — just produce or consume [ref].

There are two directions:

  • Inbound Channel Adapter — a producer endpoint. It polls a method or expression and sends every non-null return value to a channel (wrapping it as a Message).
  • Outbound Channel Adapter — a consumer endpoint. It receives messages from a channel and invokes a void-returning "sink" method. There is no reply — the message ends here.
Mission tie-in: Channel adapters are the on-ramps and off-ramps of your integration flows. Every file adapter, JMS adapter, HTTP adapter, mail adapter, and so on is built on this pattern. Understanding the base pattern means you understand every transport adapter in the framework.

1. Inbound Channel Adapter (@InboundChannelAdapter)

The inbound adapter is a SourcePollingChannelAdapter that polls a method (or expression) and sends the result to an output channel [ref].

You can configure it with the @InboundChannelAdapter annotation on any method that returns a non-null value:

@InboundChannelAdapter(channel = "adapterChannel",
                       poller = @Poller(fixedRate = "1000"))
public String timestampSource() {
    return "adapter-" + Instant.now();
}

The contract:

  • The method is invoked on each poll cycle.
  • If the return value is non-null, it's wrapped in a Message and sent to the named channel.
  • If the return value is null, the poll cycle is skipped (no message sent).
  • The annotation is placed on a method (not on a @Bean method — it works on a plain method inside a @Configuration class or a @Component).

The same pattern expressed with the Java DSL:

@Bean
public IntegrationFlow inboundFlow() {
    return IntegrationFlow.from(
            (MessageSource<String>) () ->
                    MessageBuilder.withPayload("dsl-" + Instant.now()).build(),
            c -> c.poller(Pollers.fixedRate(1500)))
            .channel("dslChannel")
            .get();
}

The DSL form gives you more control — you can chain transformers, filters, or handlers directly without creating intermediate channel beans.

2. Outbound Channel Adapter (@ServiceActivator as sink)

The outbound channel adapter receives messages from a channel and passes the payload to a consumer method. The method should have a void return type — it's the end of the flow [ref].

@ServiceActivator(inputChannel = "outboundSink")
public void handleOutbound(String payload) {
    log.info("[outbound-consumer] handled: {}", payload);
}

If the channel is a PollableChannel, add a @Poller:

@ServiceActivator(channel = "queueChannel",
    poller = @Poller(fixedRate = "3000"))
public void handleOutbound(String payload) { ... }

Unlike the inbound adapter, the outbound adapter is just a @ServiceActivator that happens to be a sink — it uses the same endpoint infrastructure you've seen in previous lessons.

3. Expression-based adapters

Instead of a ref+method pair, you can use SpEL expressions directly [ref]:

<int:inbound-channel-adapter channel="channel1"
    expression="@systemPropertySource.getProperty('my.property')"
    poller="defaultPoller"/>

<int:outbound-channel-adapter channel="channel2"
    expression="'Received: '.concat(payload)"/>

For inbound adapters, the expression is evaluated on each poll. A non-null result becomes the message payload. For outbound adapters, the expression acts as a void-returning consumer.

Scripts (Groovy, Ruby, etc.) can also be used via the script sub-element, with optional refresh-check-delay for hot-reloading.

4. Default poller and implicit channels

If you omit the poller from an inbound adapter, a single default poller must be registered in the context. The default trigger is a PeriodicTrigger with a 1 second fixed delay [ref].

If you omit both channel and id on an outbound adapter, the framework creates an implicit DirectChannel named after the adapter's id.

Key takeaways

  • Inbound Channel Adapter — polls a producer method/expression; non-null results become messages on the output channel. Backed by SourcePollingChannelAdapter.
  • Outbound Channel Adapter — a sink endpoint: receives messages and passes payloads to a void-returning method. Backed by @ServiceActivator (or EventDrivenConsumer / PollingConsumer).
  • Three configuration styles: annotation (@InboundChannelAdapter), Java DSL (IntegrationFlow.from(…, poller)), and XML (<int:inbound-channel-adapter> / <int:outbound-channel-adapter>).
  • Expression and script support — SpEL expressions and scripting languages can replace ref+method for dynamic adapters.
  • Default poller — if not specified, a default with PeriodicTrigger (1s fixed delay) is used. A default poller bean must be registered if multiple adapters share the same schedule.
  • Channel adapters are the foundation of all transport-specific adapters (file, JMS, HTTP, mail, etc.).

Action / Assessment

Test your understanding of channel adapters.

What is the primary purpose of an inbound channel adapter?

  • To consume messages from a channel and invoke a sink method
  • To poll a producer method and send non-null results to a channel
  • To route messages between channels
  • To transform message payloads

An inbound channel adapter polls a source (method, expression, or MessageSource) and sends every non-null result to the output channel.

What happens when an @InboundChannelAdapter method returns null?

  • A null message is sent
  • The poll cycle is skipped — no message is produced
  • An exception is thrown
  • The adapter stops polling

null return means "nothing to produce this cycle". The framework skips the send and polls again on schedule.

Which framework endpoint backs @InboundChannelAdapter?

  • EventDrivenConsumer
  • SourcePollingChannelAdapter
  • PollingConsumer
  • MessageProducer

@InboundChannelAdapter is a SourcePollingChannelAdapter — it polls a MessageSource (the annotated method) and forwards to the output channel.

What must an outbound channel adapter method return?

  • A Message
  • A non-null payload
  • void
  • A boolean

An outbound channel adapter is a sink — it receives messages and passes payloads to a void method. There's no further output.

What type is a @ServiceActivator used as an outbound channel adapter on a DirectChannel?

  • PollingConsumer
  • EventDrivenConsumer
  • SourcePollingChannelAdapter
  • ChannelInterceptor

On a DirectChannel (SubscribableChannel), the @ServiceActivator is an EventDrivenConsumer — messages arrive by push. On a QueueChannel, the same annotation with @Poller becomes a PollingConsumer.

What is the default trigger for a poller when none is specified on an inbound adapter?

  • fixedRate of 500ms
  • cron expression "0/5 * * * * *"
  • PeriodicTrigger with 1 second fixed delay
  • There is no default; a poller must always be provided

The default trigger is a PeriodicTrigger with a 1 second fixed delay. A default poller bean must be registered if multiple adapters share this default schedule.

What happens if an inbound channel adapter is configured without an explicit channel?

  • Messages are discarded
  • An implicit DirectChannel is created with the adapter's id as the channel name
  • The adapter uses the errorChannel
  • A runtime exception is thrown

If channel is omitted, the framework creates an implicit DirectChannel named after the id attribute (XML config) or the bean name.

Which three configuration styles are available for channel adapters?

  • YAML, JSON, TOML
  • Annotations, Java DSL, XML
  • Properties, XML, SQL
  • Java, Kotlin, Groovy DSL

Spring Integration supports three configuration styles for channel adapters: annotations (@InboundChannelAdapter/@ServiceActivator), Java DSL (IntegrationFlow), and XML namespace.
