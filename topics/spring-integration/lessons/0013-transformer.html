Transformer

An endpoint that modifies the message payload, headers, or both — the Swiss Army knife of message transformation.

Why this lesson exists

A transformer is a Message Endpoint that converts a message's payload, headers, or both. Unlike a channel adapter (which connects to external systems) or a bridge (which forwards unchanged), a transformer modifies the message in flight. This is one of the most commonly used endpoints in any integration flow [ref].

Spring Integration provides many built-in transformers (Object-to-String, JSON, Stream, Avro, Protobuf) and a powerful SpEL expression transformer. You can also write a plain POJO method with @Transformer for custom transformations.

Key rule: A transformer must not return null. If the method returns null, the framework throws a MessageTransformationException. This is because the requiresReply attribute is always true for transformers. If you need a conditional path that may return nothing, use @ServiceActivator instead.

1. @Transformer annotation

The simplest transformer is a POJO method annotated with @Transformer [ref]:

@Transformer(inputChannel = "in", outputChannel = "out")
public String upper(String payload) {
    return payload.toUpperCase();
}

The method can accept @Header and @Headers parameters to access message headers. The return value becomes the new payload. Because the method is on a plain POJO (not a @Bean), the annotation is processed by a TransformerAnnotationPostProcessor that wraps the method in a TransformerFactoryBean.

2. Built-in transformers

Spring Integration ships with several ready-to-use transformers [ref]:

  • ObjectToStringTransformer — calls toString() on the payload
  • ObjectToMapTransformer — converts a Java object to a Map<String, Object>
  • MapToObjectTransformer — converts a Map back to an object
  • JsonToObjectTransformer / ObjectToJsonTransformer — JSON marshalling (needs jackson-databind on classpath)
  • StreamTransformer — converts InputStream to byte[] or String
  • FileToStringTransformer / FileToByteArrayTransformer
  • SyslogToMapTransformer — parses syslog messages

These are configured as @Bean methods with @Transformer annotation, or via the DSL's Transformers utility class:

@Bean
@Transformer(inputChannel = "in", outputChannel = "out")
public ObjectToStringTransformer toStringTransformer() {
    return new ObjectToStringTransformer();
}

3. SpEL expression transformer

The DSL and XML support transformers defined as SpEL expressions [ref]:

@Bean
public IntegrationFlow spelFlow() {
    return IntegrationFlow.from("in")
            .transform("payload.toUpperCase() + ' via SpEL'")
            .channel("out")
            .get();
}

You can also use .transform(expression, Class) to specify a target type, or .transform(GenericTransformer) for a lambda. The expression can access payload, headers, and any beans in the application context.

4. JSON transformers

JSON transformation is particularly common in microservice integrations. The ObjectToJsonTransformer serializes a Java object to a JSON string (or byte[]), and JsonToObjectTransformer deserializes it back [ref].

@Bean
public IntegrationFlow jsonRoundTrip() {
    return IntegrationFlow.from("in")
            .transform(Transformers.toJson())
            .transform(Transformers.fromJson(Person.class))
            .channel("out")
            .get();
}

The Transformers utility class (in org.springframework.integration.dsl) provides static factory methods for all built-in transformers in a DSL-friendly form.

5. Header filter

The header filter is a special transformer that removes specified headers from the message [ref]:

@Bean
public IntegrationFlow filterFlow() {
    return IntegrationFlow.from("in")
            .headerFilter("sensitive-header-name")
            .channel("out")
            .get();
}

This is useful before sending messages to external systems or untrusted consumers, ensuring sensitive headers (credentials, internal routing info) are stripped.

Key takeaways

  • Transformer is an endpoint that modifies a message's payload, headers, or both.
  • requiresReply is always true — a transformer must not return null. Doing so throws MessageTransformationException.
  • @Transformer annotation works on a plain POJO method (not a @Bean method, unless returning a transformer instance). The method's return value becomes the new payload.
  • Built-in transformers cover common conversions: Object-to-String, JSON, Map, Stream, File, Syslog.
  • SpEL expression transformers are defined inline in the DSL with .transform("expression").
  • JSON transformers need jackson-databind on the classpath.
  • Header filter strips named headers — useful for security/privacy before external dispatch.

What happens if a @Transformer method returns null?

  • The message is silently discarded
  • The framework logs a warning and continues
  • A MessageTransformationException is thrown
  • The message is sent to the error channel

Because requiresReply is always true for transformers, returning null causes a MessageTransformationException. Use @ServiceActivator instead if you need a conditional path that may return nothing.

Which of these is a valid way to configure a transformer?

  • @Transformer on a POJO method
  • @Bean + @Transformer on a transformer instance
  • DSL .transform() step
  • All of the above

Transformers can be configured via @Transformer annotation on a POJO method, @Bean + @Transformer on a transformer instance, or the DSL .transform() step.

Where is the Transformers utility class located?

  • org.springframework.integration.transformer.support
  • org.springframework.integration.config
  • org.springframework.integration.dsl
  • org.springframework.integration.transformer

Transformers (note the plural) is in org.springframework.integration.dsl, providing static factory methods for common transformers like toJson(), fromJson(), etc.

What does a header filter transformer do?

  • Filters messages based on header values
  • Removes named headers from the message
  • Validates required headers exist
  • Copies headers to a separate channel

The header filter removes specified headers by name, useful for stripping sensitive or internal headers before forwarding to external systems.

Which dependency must be on the classpath for JSON transformers to work?

  • gson
  • jackson-databind
  • json-path
  • json-simple

ObjectToJsonTransformer and JsonToObjectTransformer require jackson-databind in the classpath.

What is the syntax for a SpEL expression transformer in the DSL?

  • .spel("expression")
  • .expression("payload")
  • .transform("payload.toUpperCase()")
  • .convert("expression")

The .transform() step accepts a SpEL expression string as payload transformation logic.

How does a transformer differ from a channel adapter?

  • A transformer only sends; an adapter only receives
  • A transformer connects to external systems
  • A transformer modifies messages in flight; an adapter connects to an external system
  • They are identical

A channel adapter connects an integration flow to an external system (file, JMS, Kafka, etc.). A transformer modifies the message content within the flow.
