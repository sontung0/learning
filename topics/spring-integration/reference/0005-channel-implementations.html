Message Channel Implementations

Seven channels, one decision guide.

Quick reference table

ImplementationInterfaceDeliveryThreadingBufferingUse case
DirectChannel Subscribable Point-to-point Caller's thread None Synchronous flow, single tx boundary, ~80% of cases
QueueChannel Pollable Point-to-point Scheduler (poller) BlockingQueue Buffered work queue, rate-limited consumer
PublishSubscribeChannel Subscribable Broadcast Caller's thread (or executor) None Event notifications, multiple independent listeners
ExecutorChannel Subscribable Point-to-point Executor thread pool None Fire-and-forget, decouple producer from consumer thread
PriorityChannel Pollable Point-to-point Scheduler (poller) PriorityBlockingQueue Ordered processing by priority header
RendezvousChannel Pollable Point-to-point Both sides block Zero-capacity (SynchronousQueue) Guaranteed handoff, no buffering
FluxMessageChannel Reactive (Publisher) Broadcast (reactive) Reactor scheduler Back-pressure aware Reactive pipelines with Project Reactor

Dispatcher configuration (DirectChannel / ExecutorChannel)

DirectChannel ch = new DirectChannel();
ch.setFailover(false);                          // default: true
ch.setLoadBalancingStrategy(null);              // "none" — fixed order; default: round-robin

QueueChannel capacity

new QueueChannel();       // unbounded — dangerous in production
new QueueChannel(25);     // bounded — always do this

PublishSubscribeChannel executor

new PublishSubscribeChannel();                          // synchronous broadcast
new PublishSubscribeChannel(someExecutor());             // async broadcast

Priority header (string key)

MessageBuilder.withPayload("urgent")
    .setHeader("priority", 10)
    .build();
