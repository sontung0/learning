MessageChannel Interface & Hierarchy

Quick-reference for the three core channel contracts.

Interface hierarchy

MessageChannel                   // send(Message), send(Message, long)
  ├── SubscribableChannel        // subscribe(), unsubscribe() — push
  │     └── DirectChannel, PublishSubscribeChannel,
  │         ExecutorChannel, FluxMessageChannel
  └── PollableChannel            // receive(), receive(long) — pull
        └── QueueChannel, PriorityChannel, RendezvousChannel

Interface definitions

public interface MessageChannel {
    boolean send(Message message);
    boolean send(Message message, long timeout);
}

public interface SubscribableChannel extends MessageChannel {
    boolean subscribe(MessageHandler handler);
    boolean unsubscribe(MessageHandler handler);
}

public interface PollableChannel extends MessageChannel {
    Message<?> receive();
    Message<?> receive(long timeout);
}

send() semantics

send(msg)Blocks indefinitely (timeout = -1)true on delivery; false on failure

Push vs Pull trade-offs

DimensionSubscribableChannel (push)PollableChannel (pull)
ThreadingSender's thread (or configured executor)Scheduler (poller) thread
BufferingNone — immediate dispatch or rejectQueue-backed — messages accumulate
Back-pressureSender blocks (same thread)Queue grows (bounded or unbounded)
Transaction scopeSingle thread — tx crosses channelPoller tx ends; consumer runs separately
Consumer controlFramework decides when to invokeConsumer pulls at its own rate
