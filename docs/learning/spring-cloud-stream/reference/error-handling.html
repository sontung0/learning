Error Handling

A compact decision guide for failures while consuming messages.

NeedMechanismOutcome
Transient failureConsumer retryInvoke the handler again; defaults to 3 attempts.
Inspect or react in this appError channelReceive an ErrorMessage containing the failure.
Preserve exhausted failureBinder DLQ/DLQ topicPublish the failed record to durable broker storage for later action.

Useful Properties

spring.cloud.stream.bindings.<binding>.consumer.max-attempts=3
spring.cloud.stream.bindings.<binding>.consumer.back-off-initial-interval=1000
spring.cloud.stream.bindings.<binding>.consumer.retryable-exceptions.java.lang.IllegalStateException=false

# Kafka binder
spring.cloud.stream.kafka.bindings.<binding>.consumer.enable-dlq=true

# Rabbit binder
spring.cloud.stream.rabbit.bindings.<binding>.consumer.auto-bind-dlq=true

Remember

  • Retry is for failures that may succeed later; do not retry a known-invalid message indefinitely.
  • An error channel is application-local handling; a DLQ is broker-persisted recovery work.
  • DLQ names and options differ by binder. For Kafka, the default name is error.<destination>.<group>.
