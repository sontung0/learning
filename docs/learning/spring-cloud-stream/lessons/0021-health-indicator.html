Health Indicator

Expose binder health through Spring Boot Actuator — and know when an unused binder silently drags your status to DOWN.

1. The Binder Health Indicator

Spring Cloud Stream registers a health indicator for binders under the name binders. It integrates with Spring Boot Actuator's health endpoint so that platform orchestration (Kubernetes liveness/readiness, load balancers) can react to binder connectivity.

To use it, you need both web and actuator dependencies on your classpath. The health endpoint is then available at /actuator/health.

2. Enabling & Disabling

PropertyEffect
management.health.binders.enabled (unset)Falls back to management.health.defaults.enabled — enabled by default
management.health.binders.enabled=trueExplicitly enable binder health checks
management.health.binders.enabled=falseCompletely disable out-of-the-box binder health indicators
Default is on. You don't need to set anything to get binder health — it's enabled unless you opt out.

3. Seeing the Details

By default, /actuator/health returns only the top-level status (e.g. UP). To see the per-binder details that feed that status, expose them:

management.endpoint.health.show-details=ALWAYS

With this, the response includes each binder's individual health — useful for diagnosing which binder is degraded while the overall status may still be UP.

4. Health Indicators Are Binder-Specific

Each binder implementation decides how it checks health. Not all binders provide a health indicator. The Kafka binder, for example, may report DOWN if no destinations are registered by that binder — a behavior that becomes important in multi-binder scenarios.

5. The Unused-Binder Trap

This is the most important practical lesson on this page. Consider an app with both the Kafka binder and the Kafka Streams binder on the classpath, but only the Kafka Streams binder is actually used (only Kafka Streams bindings are declared).

  1. The Kafka binder is present but unused — no destinations registered.
  2. The Kafka binder's health check sees no destinations and reports DOWN.
  3. The top-level application health becomes DOWN — even though the app is perfectly healthy.
Fix: remove the unused Kafka binder dependency from the application. If you're not using a binder, don't ship it on the classpath — its health check can poison the overall status.

6. Custom & Additional Health Indicators

You can extend or replace binder health checks with your own HealthIndicator beans:

GoalHow
Replace binder indicators entirelySet management.health.binders.enabled=false, then provide your own HealthIndicator beans (Spring Boot's infrastructure still picks them up)
Augment binder indicatorsLeave binder indicators enabled and add your own HealthIndicator beans alongside them

7. Multi-Binder: Disabling a Subset

With multiple binders, health indicators are enabled for all by default. To disable health checks for only a subset of binders, set management.health.binders.enabled=false in that binder's environment-specific configuration (see Connecting to Multiple Systems for how environment-scoped properties work).
